# GeriaPharm — مرجع دارودرمانی سالمندان

مرجع فارسی دارودرمانی سالمندان با رابط راست‌به‌چپ، فونت محلی **وزیرمتن**، مطالعه آفلاین، بررسی نسخه، موتورهای هوشمند آفلاین (جست‌وجوی BM25/Fuzzy، شباهت برداری جایگزین‌ها و مدل ریسک رگرسیون لجستیک) و پنل مدیریت متصل به بک‌اند.

## اجرای سریع روی این دستگاه

```sh
npm install
npm run setup
npm run dev
```

به نشانی `http://localhost:5173` بروید. دستور توسعه، رابط و API را هم‌زمان اجرا می‌کند و به‌صورت پیش‌فرض از دیتابیس محلی SQLite استفاده می‌شود.

- ایمیل محلی: مقدار `ADMIN_EMAIL` در فایل `.env`
- رمز اولیه: مقدار `ADMIN_PASSWORD` در فایل `.env`
- فایل `.env` در Git و تصویر Docker قرار نمی‌گیرد.

بعد از ورود، رمز را در بخش مدیریت تغییر دهید. مقدار اولیه محیط فقط برای ایجاد اولین حساب استفاده می‌شود؛ تغییر دادن آن پس از ساخت دیتابیس، رمز حساب موجود را تغییر نمی‌دهد.

## استقرار پیشنهادی روی Render (فرانت‌اند + بک‌اند + PostgreSQL)

پروژه به‌صورت کامل برای استقرار یکپارچه روی **Render** با فایل **`render.yaml`** (Render Blueprint) آماده شده است. برای جزئیات کامل استقرار، اتصال دیتابیس مدیریت‌شده PostgreSQL و هماهنگی با Cloudflare Worker، فایل **`DEPLOY-RENDER.md`** را ببینید.

خلاصه تنظیمات Render:
- **Build Command:** `npm install && npm run build`
- **Start Command:** `npm start`
- **Health Check:** `/api/health` (پاسخ `{"status":"ok","database":"postgres"}`)
- **دیتابیس:** اتصال خودکار به **Render PostgreSQL** از طریق `DATABASE_URL` (بدون از دست رفتن داده‌ها پس از دیپلوی یا ری‌استارت)

## استقرار با Docker (اختیاری)

```sh
docker compose up -d --build
```

## متغیرهای محیطی

| متغیر | کاربرد |
| :--- | :--- |
| `DATABASE_URL` | نشانی اتصال PostgreSQL (در Render به‌صورت خودکار تزریق می‌شود؛ اولویت بالاتر از SQLite دارد) |
| `DATABASE_PATH` | مسیر SQLite برای توسعه محلی؛ پیش‌فرض `data/geriapharm.sqlite` |
| `APP_ORIGIN` | یک یا چند نشانی مجاز سایت با ویرگول (مثلاً `https://geriapharm.arshid.tech,https://geriapharm.onrender.com`) |
| `ADMIN_EMAIL` | ایمیل مدیر اولیه یا حساب هدف در بازیابی رمز |
| `ADMIN_PASSWORD` | رمز اولیه؛ حداقل ۱۲ نویسه، بدون مقدار پیش‌فرض عمومی |
| `ADMIN_PASSWORD_FILE` | جایگزین اختیاری برای خواندن رمز از فایل secret |
| `PORT` | پورت سرور (در Render خودکار تزریق می‌شود؛ پیش‌فرض `3001`) |
| `HOST` | در تولید و Render پیش‌فرض `0.0.0.0` و در توسعه محلی `127.0.0.1` |
| `COOKIE_SECURE` | در تولید `true`؛ فقط برای آزمون HTTP محلی `false` |
| `TRUST_PROXY_HOPS` | روی Render به‌صورت خودکار `1` است |
| `BACKUP_DIR` | مسیر پشتیبان محلی SQLite؛ پیش‌فرض `data/backups` |

## ورود و امنیت مدیریت

- رمز با `scrypt`، salt تصادفی و مقایسه زمان‌ثابت بررسی می‌شود؛ رمز خام در دیتابیس ذخیره نمی‌شود.
- نشست تصادفی هشت‌ساعته در کوکی `HttpOnly` و `SameSite=Strict` قرار می‌گیرد. در HTTPS، کوکی `Secure` است. فقط هش شناسه نشست روی سرور ذخیره می‌شود.
- همه مسیرهای `/api/admin/*` به نشست معتبر نیاز دارند؛ درخواست‌های تغییردهنده به مبدأ مجاز (`APP_ORIGIN`) و CSRF token متصل به نشست نیاز دارند.
- تغییر رمز همه نشست‌های آن حساب را باطل می‌کند. ویرایش‌های فهرست با شماره نسخه (`If-Match`) کنترل می‌شوند.
- Helmet هدرهای امنیتی و CSP سخت‌گیرانه (`script-src 'self'` بدون `unsafe-inline`) را تنظیم می‌کند.

### بازیابی رمز مدیر

```sh
npm run admin:reset
```

این دستور هم با PostgreSQL (`DATABASE_URL`) و هم با SQLite (`DATABASE_PATH`) کار می‌کند.

## رفتار آفلاین و همگام‌سازی

Service Worker پوسته برنامه، فونت وزیرمتن، آیکون‌ها و اسکریپت تم را ذخیره می‌کند و مسیرهای `/api/` را کش نمی‌کند (`NetworkOnly`). آخرین فهرست دریافت‌شده از سرور در IndexedDB (و جایگزین LocalStorage) ذخیره می‌شود تا مطالعه، جست‌وجو و بررسی نسخه به‌صورت آفلاین در دسترس باشند.

## نظرسنجی UMARS و خروجی داده

پرسشنامه UMARS شامل ۳ پرسش جمعیت‌شناختی و ۲۵ پرسش استاندارد است (سوالات ۱۲ تا ۱۵ با مقیاس ۱ تا ۶ و بقیه ۱ تا ۵). پاسخ‌ها بی‌نام در جدول `survey_responses` ذخیره می‌شوند و مدیر می‌تواند خروجی JSON یا CSV سازگار با Excel دریافت کند. جزئیات در `GUIDE-ADMIN-EXPORT.md`.
